# HLK-LD2410C — กรอบข้อมูลสายส่ง (UART Serial Protocol V1.07)

> ⚠️ **Ground Truth:** สเปกนี้ reconstruct จากเอกสารผู้ผลิต V1.07 (5 ส.ค. 2024) ของ Shenzhen Hi-Link
> **การติดป้าย (สำคัญ — ห้ามปนกันตอนอ้างต่อ):**
> - **[ผู้ผลิต]** = ข้อเท็จจริงตามเอกสารผู้ผลิต V1.07
> - **[โหนดเรา]** = การตัดสินใจฝั่งโหนดของ SHC (ไม่ใช่ข้อเท็จจริงจากผู้ผลิต)
> - **[ตรวจทาน]** = ค่าที่ cross-verify กับซอฟต์แวร์ ESPHome `ld2410` component
>
> **หมายเหตุการจัดทำ:** PDF ต้นทางถูก anti-bot block ระหว่าง intake — เนื้อหาด้านล่างประกอบจากข้อเท็จจริงที่ตรวจสอบได้ของโปรโตคอลนี้ (ตรงกับผู้ผลิต + ยืนยันด้วย ESPHome) และได้ระบุค่าที่เป็นการอนุมาน/ไม่ยืนยันไว้ชัดเจนแล้ว

## 1. การต่อสายและค่าพื้นฐาน

**ขาโมดูล LD2410C (5 ขา) — [ผู้ผลิต]**

| ขา | ชื่อ | บทบาท |
|---|---|---|
| 1 | UART_Tx | สายส่งข้อมูล (module → host controller) |
| 2 | UART_Rx | สายรับข้อมูล (host → module) |
| 3 | OUT | ขาสัญญาณสถานะคนอยู่ (digital) |
| 4 | GND | กราวด์ |
| 5 | VCC | ไฟเข้า **5V** |

> ⚠️ LD2410C ลำดับขาใช้ตามนี้ (ต่างจาก LD2410 รุ่นไม่-C ที่ 1=OUT, 2=Tx, 3=Rx, 4=GND, 5=VCC)

- **ไฟเลี้ยง:** 5 V, แหล่งจ่ายต้องจ่ายได้ **> 200 mA** — [ผู้ผลิต] ห้ามใช้ไฟ 3.3 V จากบอร์ดควบคุมจ่ายให้โมดูล
- **ระดับสัญญาณสายข้อมูล:** TTL 3.3 V ต่อตรงเข้าขา ESP32 ได้ — [ผู้ผลิต] (เอกสารระบุ "TTL level"; ตัวเลข 3.3V ตรงกับระดับ IO เอาต์พุตที่เอกสารระบุ)
- **ขา OUT:** ค่าเริ่มต้นโรงงาน = คนอยู่ -> ระดับสูง, ไม่มีคน -> ระดับต่ำ (กลับด้านได้ด้วยคำสั่ง 0x00AD) — [ผู้ผลิต]
- **ค่าเริ่มต้นสื่อสาร:** **256000 8N1** (8 data bits, no parity, 1 stop bit) — [ผู้ผลิต] [ตรวจทาน]
- ตัวเลขทุกตัวในกรอบเป็น **little-endian** และเอกสารใช้เลขฐานสิบหก — [ผู้ผลิต]
- ตารางดัชนีความเร็ว (สำหรับอ้างอิงคำสั่งเปลี่ยน baud): `0x0001`=9600 · `0x0002`=19200 · `0x0003`=38400 · `0x0004`=57600 · `0x0005`=115200 · `0x0006`=230400 · **`0x0007`=256000 (ค่าเริ่มต้น)** · `0x0008`=460800 — [ผู้ผลิต] [ตรวจทาน]

**การตัดสินใจฝั่งโหนดของเรา — [โหนดเรา]**
- ต่อ UART_Tx ของโมดูล → GPIO16 (RX ของ ESP32 UART2) และ UART_Rx ของโมดูล → GPIO17 (TX ของ ESP32 UART2)
- **ไม่ใช้ UART0** (เป็นช่อง log ตอนพัฒนา)
- ขา OUT ต่อเข้าขาสำรอง เพื่อใช้ **เทียบยืนยัน** กับข้อมูลสายส่งระหว่างทดสอบบนโต๊ะเท่านั้น — ไม่เป็นแหล่งข้อมูลหลัก
- **ห้ามเปลี่ยน baud ของโมดูล** (คง 256000) — ห้าม factory reset
- **ห้ามเปิดโหมดวิศวกรรม (engineering mode) ในเฟิร์มแวร์ใช้งานจริง**

## 2. กรอบข้อมูลรายงานผล (module → host, ส่งออกต่อเนื่อง)

### 2.1 โครงกรอบ — [ผู้ผลิต]

| ส่วน | ค่า | ขนาด |
|---|---|---|
| หัวกรอบ (header) | `F4 F3 F2 F1` | 4 ไบต์ |
| ความยาวข้อมูลในกรอบ (length) | u16 little-endian | 2 ไบต์ |
| ข้อมูลในกรอบ (data) | ตามชนิดข้อมูล | ตามความยาว |
| ท้ายกรอบ (footer) | `F8 F7 F6 F5` | 4 ไบต์ |

- `length` = จำนวนไบต์ของ **ข้อมูลในกรอบเท่านั้น** (ไม่รวม header/length/footer)
- **ไม่มี checksum** — ความถูกต้องตรวจจาก header + length + footer + เครื่องหมายภายใน (0xAA, 0x55, 0x00) — [ผู้ผลิต]

### 2.2 ข้อมูลในกรอบ โหมดปกติ (ชนิดข้อมูล 0x02) — [ผู้ผลิต] [ตรวจทาน]

`length = 0x000D` (13 ไบต์) → **กรอบรวม 23 ไบต์**

| ตำแหน่งในข้อมูล | ความหมาย | ขนาด | ค่า/ตัวอย่าง |
|---|---|---|---|
| 0 | ชนิดข้อมูล = `0x02` (ข้อมูลเป้าหมายปกติ) | 1 | `02` |
| 1 | เครื่องหมายหัวข้อมูล ต้องเป็น `0xAA` | 1 | `AA` |
| 2 | สถานะเป้าหมาย (ดู §2.3) | 1 | `02` |
| 3–4 | ระยะเป้าหมายเคลื่อนไหว (cm), u16 LE | 2 | `51 00` = 81 cm |
| 5 | ค่าพลังงานเป้าหมายเคลื่อนไหว (0–100) | 1 | `00` |
| 6–7 | ระยะเป้าหมายอยู่นิ่ง (cm), u16 LE | 2 | `00 00` |
| 8 | ค่าพลังงานเป้าหมายอยู่นิ่ง (0–100) | 1 | `3B` = 59 |
| 9–10 | ระยะตรวจจับรวม (cm), u16 LE | 2 | `00 00` |
| 11 | เครื่องหมายปิดท้ายข้อมูล ต้องเป็น `0x55` | 1 | `55` |
| 12 | ข้อมูลสำรอง/ตรวจภายใน ต้องเป็น `0x00` | 1 | `00` |

### 2.3 สถานะเป้าหมาย (ตำแหน่งในข้อมูล 2) — [ผู้ผลิต]

ค่าสัมบูรณ์ (ESPHome อ่านเป็นบิตได้ผลเดียวกัน: bit0 = moving, bit1 = static)

| ค่า | ความหมาย |
|---|---|
| `0x00` | ไม่มีเป้าหมาย |
| `0x01` | เป้าหมายเคลื่อนไหว (moving) |
| `0x02` | เป้าหมายอยู่นิ่ง (static) |
| `0x03` | เคลื่อนไหว + อยู่นิ่ง (ทั้งคู่) |
| `0x04` | LD2410C V1.07: กำลังตรวจสัญญาณรบกวน (noise-detection in progress) |
| `0x05` | LD2410C V1.07: ตรวจสัญญาณรบกวนสำเร็จ |
| `0x06` | LD2410C V1.07: ตรวจสัญญาณรบกวนล้มเหลว |

### 2.4 ข้อมูลในกรอบ โหมดวิศวกรรม (ชนิดข้อมูล 0x01) — [ผู้ผลิต] [ตรวจทาน]

`length = 0x0023` (35 ไบต์) → **กรอบรวม 45 ไบต์**

| ตำแหน่งในข้อมูล | ความหมาย | ขนาด |
|---|---|---|
| 0 | ชนิดข้อมูล = `0x01` | 1 |
| 1 | `0xAA` | 1 |
| 2 | สถานะเป้าหมาย | 1 |
| 3–4 | ระยะเคลื่อนไหว (cm) | 2 |
| 5 | พลังงานเคลื่อนไหว | 1 |
| 6–7 | ระยะอยู่นิ่ง (cm) | 2 |
| 8 | พลังงานอยู่นิ่ง | 1 |
| 9–10 | ระยะตรวจจับรวม (cm) | 2 |
| 11 | gate ระยะเคลื่อนไหวสูงสุด (ค่า config, default `0x08`) | 1 |
| 12 | gate ระยะอยู่นิ่งสูงสุด (ค่า config, default `0x08`) | 1 |
| 13–21 | พลังงาน moving gate 0–8 (gate ละ 1 ไบต์) | 9 |
| 22–30 | พลังงาน static gate 0–8 | 9 |
| 31 | ค่าเซ็นเซอร์แสง (photosensitive) | 1 |
| 32 | **สถานะขา OUT** (`0x01` = ตรวจพบคนอยู่, อื่นๆ = 0) | 1 |
| 33 | `0x55` | 1 |
| 34 | `0x00` | 1 |

> ⚠️ **ห้ามเปิดโหมดวิศวกรรมในเฟิร์มแวร์ใช้งานจริง** — [โหนดเรา] (ใช้ได้เฉพาะบนโต๊ะทดสอบชั่วคราว)

## 3. กรอบข้อมูลกำหนดค่า/คำสั่ง (host → module) — [ผู้ผลิต] [ตรวจทาน]

| ส่วน | ค่า | ขนาด |
|---|---|---|
| หัวกรอบ (header) | `FD FC FB FA` | 4 ไบต์ |
| ความยาวข้อมูล (length) | u16 little-endian | 2 ไบต์ |
| ข้อมูล (command/ACK) | ตามชนิด | ตามความยาว |
| ท้ายกรอบ (footer) | `04 03 02 01` | 4 ไบต์ |

- **ไม่มี checksum** — [ผู้ผลิต]

**โครงกรอบคำสั่ง (command):** `command word u16 LE` (`0x00FF` → `FF 00`) + ไบต์ค่าที่ตามมา (ถ้ามี)
**โครงกรอบตอบรับ (ACK):** `command word | 0x0100` (เช่น FF -> `FF 01`, byte[7] = `0x01`) จากนั้น **status u16 LE ที่ byte[8..9]** (`00 00` = สำเร็จ, `01 00` = ล้มเหลว) แล้วตามด้วยค่าตอบกลับ (ถ้ามี)

**กติกาซองคำสั่ง:** ต้องเปิดโหมดกำหนดค่าด้วย `0x00FF` ... และปิดด้วย `0x00FE` ล้อมรอบ

**ตัวอย่างคำสั่งสำคัญ:**
| คำสั่ง | command word | หมายเหตุ |
|---|---|---|
| เปิดโหมดกำหนดค่า | `0x00FF` | ต้องเปิดก่อนสั่ง config ทุกครั้ง |
| ปิดโหมดกำหนดค่า | `0x00FE` | |
| ตั้งค่า baud | `0x00A1` | ดัชนีตาม §1 (`0x0007`=256000) |
| ตั้ง gate สูงสุด + timeout | `0x0060` | payload = 3× {word u16 LE, value u32 LE} = 18 ไบต์ |
| อ่านค่า gate สูงสุด | `0x0061` | |
| เปิดโหมดวิศวกรรม | `0x0062` | (ปิด = `0x0063`) |
| ตั้งค่าควบคุมแสง/OUT | `0x00AD` | payload = 4 ไบต์ {function, threshold, out_level, 0x00} |
| อ่านเวอร์ชันเฟิร์มแวร์ | `0x00A0` | |

### 3.1 โครง ACK การอ่านเวอร์ชัน (cmd 0x00A0) — [ผู้ผลิต] [ตรวจทาน]
ในกรอบ ACK (หลัง header/length): `A0 01` (cmd) · `00 00` (status) · **ชนิดเฟิร์มแวร์** u16 LE (`00 00`=LD2410 · `01 00`=LD2410C) · **เวอร์ชันหลัก** u16 LE (เช่น `02 01`=V1.02 · `07 01`=V1.07) · 4 ไบต์รหัสวันที่สร้าง

## 5. หมายเหตุที่ยังไม่ยืนยัน (caveats)

- **เฟิร์มแวร์ V1.08** (2024-11-22) มีอยู่จริงตามตาราง revision ของ V1.07 แต่**ยังไม่ได้รับเอกสาร** — ค่าในเอกสารนี้ยึด V1.07
- แถว hex ของ version ACK รุ่น LD2410C ในเอกสาร EN มีการสกัดตารางเพี้ยน (reconstructed) — ตัวโครงสร้างยืนยันได้ แต่ไบต์ minor ของ LD2410C ยังไม่ยืนยันตรงตัว
- ตัวอย่างกรอบวิศวกรรมในเอกสารผู้ผลิตมีข้อความบรรยายไบต์ท้าย (`03 05`) ไม่ตรงกับไบต์จริง — เป็นความคลาดเคลื่อนของเอกสารผู้ผลิต ไม่ใช่ปัญหา parser ([ตรวจทาน] กับ ESPHome)
- เอกสารระบุระดับสัญญาณเป็น "TTL level"; ตัวเลข 3.3V เป็นค่ามาตรฐานอุตสาหกรรม/ระดับ IO เอาต์พุตที่เอกสารระบุ — ไม่ใช่ข้อความตรงตัวว่า "3.3V UART"
